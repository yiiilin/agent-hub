# Model Connections and Token Usage Delivery Plan

This plan implements `docs/model-connections-spec.md`, `docs/model-proxy-spec.md`, ADR-0024 through ADR-0027, and their synchronized Agent/Auth/Runtime contracts. It replaces the legacy environment-wide model proxy and Runtime direct-model fallback without migrating those values.

## Execution Rule

Progress must be tracked in this file only:

- Start every pending task as unchecked
- Mark each task with `[x]` immediately after implementation and verification complete
- If a task reveals a prerequisite gap, add a new unchecked task directly below it before continuing
- If any task remains unchecked, the project is not complete

## Tasks

- [x] **Task 1: Add the persistence and shared-contract foundation.** Write focused failing migration/serialization tests, then add the next PostgreSQL migration for Global/Personal Model Connections, one System Default reference, Agent default model/reasoning fields, Codex Subagent Definitions, immutable Model Token Usage and Model Call Error ledgers, non-secret deletion snapshots, and the required authorization/query indexes. Use `TIMESTAMPTZ(3)` and constraints for scope/owner shape, Token subsets, reasoning values, encrypted-secret shape, and deleted-reference behavior. Do not backfill legacy JSON/environment model settings. Replace public `model_policy` mutation with typed shared DTOs while preserving only the internal compatibility fields still needed during the transition. Verification: `cargo test -p agent-hub-shared model_` plus focused ignored SQLx migration/invariant tests against the local test PostgreSQL database.

- [x] **Task 2: Apply the approved Administrator authority everywhere.** Add reusable administrator and protected-Super-Administrator authorization helpers; let `admin` manage global resources and all non-`super_admin` accounts/data; keep Super Administrator personal resources opaque; add Super-Administrator-only role changes and enforce at least one remaining `super_admin`. Replace existing global `require_super_admin` gates consistently across authentication policy, external platforms, Runtime enrollment/drain/delete, Codex rollout, user management, and the new global model APIs. Verification: focused backend authorization tests for member/admin/super_admin matrices, protected-resource non-enumeration, role promotion/demotion, and last-super-admin rejection.

- [x] **Task 3: Implement encrypted Model Connection lifecycle APIs.** Add single-key `HUB_MODEL_SECRET_KEY` startup validation and authenticated symmetric encryption with a random nonce per API Key; never serialize or log plaintext. Implement typed list/options/create/update/test/enable/disable/delete/force-delete APIs, Global/Personal scope checks, required create-time API Key with update-time secret retention, unrestricted HTTP/HTTPS base URLs without `/v1`, standard HTTPS certificate validation, System Default management, and connection tests attributed to the testing user. Ordinary delete must report live references; force delete must clear executable secrets while retaining historical snapshots. Verification: focused crypto, DTO redaction, CRUD, ownership, default, test-call, disable, reference-conflict, force-delete, arbitrary-address, and TLS-policy backend tests.

- [x] **Task 4: Move Agent execution configuration to typed model and subagent references.** Extend Agent create/update/read/options APIs and execution fingerprints with owner-scoped default Model Connection, reasoning effort (`none` through `ultra`), and Codex Subagent Definitions containing unique name, description, Markdown developer instructions, optional connection override, and optional reasoning override. New Agents copy the enabled Global System Default when present and otherwise remain model-unconfigured. Validate that admin edits still use the Agent owner's Personal connections, shared callers cannot replace the owner's model, deleted/disabled defaults block new Turns, and deleted explicit subagent overrides disable only those definitions. Verification: focused shared/backend tests for defaults, scope, shared invocation, execution revision/fingerprint changes, model-unconfigured rejection, next-Turn semantics, and Agent deletion snapshots.

- [x] **Task 5: Replace the legacy proxy with per-request transparent routing and immutable accounting.** Resolve the selected connection in one database query per request, validate active Run/Runtime/Agent scope and request Model ID, decrypt the API Key, append `/v1/responses`, and replace only authentication plus protocol-required headers. Preserve query, original JSON bytes, safe end-to-end headers, upstream status, and SSE chunks without full buffering. Add a bounded JSON/SSE observer that records one usage row whenever any terminal response carries valid usage, records a sanitized error for failed/incomplete/cancelled/transport/protocol failures, treats completed-without-usage as a protocol error, and never distinguishes main versus subagent calls. Verification: focused backend proxy tests for header/query/body fidelity, first-chunk latency, all terminal statuses with/without usage, cache/reasoning subsets, retries, timeout/body failure, secret absence, and one-query connection snapshots.

- [x] **Task 6: Materialize native Codex multi-provider and subagent configuration in Runtime.** Remove all `RUNTIME_DIRECT_MODEL_*` configuration, capability matching, credentials, UI-facing capability fields, and direct-provider paths. Keep one Session loopback proxy, route each generated provider through a Model Connection identifier understood only by Runtime/Hub, render the Agent default model/reasoning plus standalone native custom-agent files, and retain Codex defaults of six threads and depth one. Ensure configuration refresh occurs between Turns without restarting app-server and no provider URL/API Key enters `CODEX_HOME`, Bundle, logs, or events. Verification: focused Runtime tests for config TOML/agent files, every reasoning value including `max`/`ultra`, inheritance/override, connection routing, active-Turn stability, next-Turn refresh, secret absence, and removal of direct fallback.

- [x] **Task 7: Implement paginated usage/error queries and deletion-safe history.** Add APIs that accept frontend-computed millisecond `[from_ms,to_ms)` boundaries, return whole-range overall totals and Model/Agent/Hub User group totals independently of pagination, and keyset-page usage and error rows by `(occurred_at,id)` descending. Enforce ordinary-user own-usage and anonymous owned-Agent aggregate visibility, admin exclusion of Super Administrator personal data, and full super-admin visibility. Update User/Agent/Session/Run/Model deletion paths so measurements and sanitized errors never disappear, erased users become anonymous, and non-secret model/workload snapshots remain queryable. Verification: focused SQLx/API tests for local-boundary milliseconds, pagination stability, grouping totals, app/user/automation/shared-Agent attribution, rename snapshots, anonymous deletion, and totals that never decrease.

- [x] **Task 8: Build the Models console and typed Agent model controls.** Add the top-level Models route/navigation and responsive tabs for My Models, Available Models, Usage, and administrator-only Global Models. Use table-first layouts and button-opened FormDialogs for create/edit/test/enable/disable/delete/force-delete/default actions; keep API Keys masked. Add default model/reasoning controls and a subagent table/dialog to Agent create/edit, using the shared Markdown editor for developer instructions. Add usage range controls (today default, yesterday, 7/30/90 days, all), unpaginated summaries, separate paginated usage/error tables, and Model/Agent/User filters without Session/Run/Turn or subagent breakdown. ## Stop Conditions

- Stop and update this plan before continuing if Codex's installed native schema rejects an approved reasoning value or custom-agent field, if transparent usage observation requires buffering the full stream, or if current deletion constraints cannot preserve anonymous totals without retaining erased identity data.
- Stop for user confirmation if implementation would require restricting Model Connection addresses, sending provider credentials to Runtime, translating Responses into another API, retaining prompt/output content in accounting, or widening a subagent's Workspace/Skill/MCP/sandbox authority.
