# Restore Session Bundles with the Active Codex Version

Agent Hub records the producing Codex version in every Session Bundle but always restores the extracted working copy with the current Active Codex Version. Promotion does not run an old-bundle-to-candidate-version restoration test, and an individual Session does not retain or fall back to its producing Codex binary. The original S3 bundle remains immutable while the active Codex version performs any supported local state upgrade; a successfully resumed Session produces a new bundle generation only at its next offline checkpoint. If the active version cannot resume the native Thread, Hub preserves the original Bundle, exposes the existing history read-only, disables further execution, and reports the recovery failure instead of silently creating a replacement Thread from Hub history.
