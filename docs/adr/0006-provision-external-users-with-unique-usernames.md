# Provision external users with unique Usernames

Each administrator-enabled external Authentication Channel is trusted to assert its user's email identity. On the first authenticated login by an unbound External Identity, a matching Hub email automatically binds that External Identity as another Authentication Channel of the existing Hub User, including when the existing email came from password registration and email verification was disabled; existing authentication channels remain valid. Once bound, the stable External Identity remains with that Hub User even if its external email later changes to an email assigned to another Hub User. Otherwise Agent Hub creates a Hub User with an immutable internal identity and a globally unique Username. Self-service password registration reserves its submitted email, rejects an email already assigned to another Hub User, and never adds a password credential to an existing account. A new Username uses the external username when available, otherwise the external email address without its domain, and otherwise `user`; conflicts receive a short stable suffix derived from the internal identity rather than exposing an external identifier. Later external username or email changes do not rename the Hub User: only an explicit Hub User action can do so. Deployments that disable email verification accept the risk of malicious email pre-registration and rely on Super Administrator remediation for real ownership conflicts.
