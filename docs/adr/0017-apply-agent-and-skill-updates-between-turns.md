# Synchronize Agent and Skill files between Turns

A Codex Turn uses one stable set of Agent and Skill files from start through completion, including every Steering Message appended to it. Changes made while the Turn is active are synchronized into the Session's Hub-managed configuration files only after it reaches a terminal state and before the next `turn/start`; they never alter an in-flight Turn. Agent Hub does not restart app-server, force a loaded Thread to reload those files, or inject their full contents into the next Turn. Codex's native discovery and loading behavior alone decides whether and how much of the updated files a later Turn reads. User credentials and Session-owned state remain isolated from these files.

Before each new Turn, Agent Hub calculates a deterministic fingerprint of the complete effective Agent Execution Configuration, including the Agent's Model Connection reference, reasoning effort, Codex Subagent Definitions, and the revision and content checksum of every associated Skill, then compares it with the fingerprint last synchronized to that Session. A difference triggers file synchronization before `turn/start`; an equal fingerprint requires no update. Timestamps alone are not authoritative, so changes to a shared Skill or model definition cannot be missed merely because the Agent record itself did not change. The fingerprint proves which files Hub synchronized, not which content Codex loaded into model context.
