# Route model protocols through a stateless gateway

ADR-0027 established a Responses-only Runtime contract and kept provider credentials in Hub. That boundary remains, but Hub no longer opens provider connections itself. After authorizing the active Run and Runtime, loading exactly one Model Connection, validating its scope, status and Model ID, and decrypting its credential, Hub sends one authenticated request envelope to an internal stateless Model Gateway. The envelope contains only that request's ID, upstream protocol, endpoint, credential, query, safe headers and original Responses body.

The Gateway embeds the exact Go module `github.com/maximhq/bifrost/core v1.7.2`. `openai_responses` is a byte-transparent fast path to `<base>/v1/responses`; `anthropic_messages` uses Bifrost's Responses/Anthropic adapters and calls `<base>/v1/messages`, returning normalized Responses JSON or SSE. Provider endpoint, credential and transport are request-scoped. The Gateway has no database, config store, plugins, durable provider keys, retry, fallback, cache, usage ledger, or prompt/output logging. Downstream cancellation closes the corresponding upstream request.

Hub remains authoritative for connection CRUD, authorization, encryption, usage/error accounting, retention and protocol snapshots. Runtime still speaks only Responses to Hub and never receives a provider endpoint or key. Compose exposes the Gateway only on `model-network`; Backend joins both Hub and model networks, while Runtime is not a member of the model network. Gateway availability is therefore required for new model calls, and Bifrost upgrades require an explicit version change plus the gateway conversion corpus.

The selected provider is inside the Model Connection owner's trust boundary: it necessarily receives the request-scoped credential and controls response content. Hub and Gateway strip credential-like response headers and never place keys in their own errors, logs, ledgers, Runtime configuration or Run events. They do not inspect or rewrite the byte-transparent OpenAI response body, because a provider can encode arbitrary output and generic content scanning would neither guarantee secrecy nor preserve the protocol contract. Administrators accept this boundary for Global connections; owners accept it for Personal connections.

This supersedes ADR-0027 only where that ADR said Hub connects directly to the provider or that every supported upstream is byte-transparent. It preserves ADR-0027's Runtime-facing Responses contract, OpenAI Responses transparency, secret boundary and Hub-owned accounting.
