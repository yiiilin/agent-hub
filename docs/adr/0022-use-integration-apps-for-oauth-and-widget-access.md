# Use Integration Apps for OAuth and Widget access

Agent Hub uses one Integration App model for OAuth clients, external Session APIs, and embedded Widgets instead of binding an OAuth App to exactly one Agent. An Integration App belongs to one trusted External Platform and Authentication Channel, may be delegated multiple Agents, and requests each Agent through an explicit `agent:<uuid>` scope. `authorization_code` tokens represent the logged-in Hub User and are constrained by both that user's current permissions and the application's current delegations; `client_credentials` tokens represent the application and may serve multiple external identities, while every resulting Session still records its own immutable platform, tenant, and External Identity origin. Removing a delegation or losing the authority used to create it invalidates that Agent scope immediately, including on already-issued tokens.

This supersedes ADR-0002's assumption that every Integration token is permanently bound to one external identity. User tokens remain identity-scoped, while application tokens are deliberately trusted across the external identities served by that application; both remain isolated from Hub-native Sessions, other Integration Apps, undelegated Agents, and the ordinary Hub control-plane API.
