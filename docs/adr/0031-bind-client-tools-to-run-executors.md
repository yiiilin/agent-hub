# Bind browser Client Tools to one Run executor

Agent Hub exposes one browser Client API to both the built-in Widget and external TypeScript clients. A trusted Integration App backend authorizes one tab-scoped Client Instance by submitting its external user identity and complete Client Tool definitions when it obtains a short-lived opaque Client Access Credential. Anonymous applications cannot submit definitions from the browser and instead use administrator-managed definitions stored on the Integration App. Credential tokens remain small random secrets whose hashes and tool JSON use the existing persisted credential record; they are not JWTs and no separate grant table is introduced.

A credential may access multiple matching Sessions, but every new Run freezes its current Grant into an immutable Run Tool Snapshot and binds one Run Tool Executor. Other tabs and devices may observe the same Session without executing that Run's tools. Credential renewal and reauthorization affect only later Runs. Runtime namespaces Client Tool names internally to avoid collisions while preserving the application's names at the Client API boundary, and Client Tools exist only when the Agent permits `integration`.

Client Tool execution is at-most-once rather than exactly-once. The SDK durably journals and claims a call before invoking application code, serializes calls from one model response, caches completed results, and never automatically reruns an invocation whose outcome is unknown. Hub accepts identical result retries idempotently, rejects divergent retries, and starts one continuation only after a normal batch is complete. A disconnect, unknown outcome, or five-minute timeout fails the Turn without replay or cross-device takeover. Applications must use `tool_call_id` for idempotency at any external side-effect boundary.

The first client is a framework-neutral browser ESM package. It keeps bearer credentials only in memory, uses a per-tab ID in `sessionStorage`, uses IndexedDB for the execution journal, resumes Session SSE by sequence, and retries message delivery with a stable key. The Integration App backend remains language-neutral HTTP and keeps `client_secret` out of browsers. Authenticated applications may omit an Origin allowlist; anonymous applications must configure exact origins. HTTP remains permitted by configuration, with interception and mixed-content risks documented rather than blocked.

This extends ADR-0022. Application Tokens remain the server-to-server authority, while Client Access Credentials are the narrow browser authority. Existing Widget endpoints remain compatibility aliases, but `/api/client/*` and `@agent-hub/client` are the canonical integration contract.
