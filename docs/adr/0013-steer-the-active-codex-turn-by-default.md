# Steer the active Codex Turn by default

When an ordinary user message arrives while a Session's Codex Turn is active, Agent Hub treats it as a Steering Message for that same Turn rather than automatically queuing a new Turn. Explicit stop still interrupts the active Turn, and an explicit wait action may queue a later Turn. Hub binds each Steering Message to the expected active Turn identifier so a delayed message cannot silently steer a different Turn; steering remains part of the current Hub Run instead of creating another Run. If Codex rejects steering because that expected Turn has already ended, Hub preserves the message in its accepted order and starts it as the next Turn instead of retrying it against a different active Turn. Every accepted Steering Message is stored and displayed as a distinct user history item with the shared Turn identifier; Hub never merges or overwrites their text.

When an offline Session is still downloading, extracting, or starting app-server and therefore has no active Turn, every ordinary message accepted before `turn/start` remains a separate Hub history item but is delivered in accepted order as input to the same new Turn. This lets Codex see all of those messages before it begins work. A message explicitly reserved for a later Turn remains queued, and ordinary messages accepted after `turn/start` follow the Steering Message rule above.
